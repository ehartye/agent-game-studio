# Planning guidance

Plan when it clarifies priorities, dependencies or uncertainty. Match detail to the task. Small changes need no planning round, fit check or design-readiness gate.

## Useful questions

| Perspective | Questions |
|---|---|
| Vision | Which player outcome matters? What tradeoff changes? |
| Design | Which rules, values and edge cases need exploration? |
| Architecture | Which systems, contracts or performance risks change? |
| Art and audio | Which assets, animations, effects and sounds are needed? |
| Writing | Which dialogue, terms or localization work changes? |
| Quality | What could fail, and what evidence distinguishes success? |

Capture relevant answers in the canonical wiki backlog or plan when maintaining it. Not every perspective needs a section or separate agent. Explicit delegation can be used within the task and host capabilities.

## Sequencing ideas

Plan near-term work in more detail than distant work. Try experiments for uncertain assumptions. Resolve real dependencies early: scale and camera before bulk assets, animation timing before dependent effects, instrumentation before measurements. Adapt these suggestions to the project.

A representative asset through the pipeline may reduce batch-production risk. Character work can imply movement, reactions, attacks and sounds; environments can imply transitions, readability and ambience. Specialist craft belongs in [the plugin map](plugin-map.md).

## Progress

Use existing project vocabulary for asset stages and milestones. Record actual approvals and selected versions when they exist. Changed contracts may warrant rechecking dependent work; explain the effect without imposing sign-off machinery.

Make useful priorities, dependencies and risks visible. Plans do not grant Studio authority over implementation or acceptance, and no duplicate repository-local plan or tracker is created.
