# Optional orientation

Use studio-start when the user wants orientation, an artifact map or help choosing a role. It is not an interceptor for every game request. Requests can go directly to a role or implementation.

## Find the wiki

Start with the wiki location already named by the user or project instructions. The [plugin map](plugin-map.md#finding-the-wiki-vault) describes configured wiki discovery. Do not infer a new repository-local state directory from an absent wiki.

Inspect relevant existing records and source only as needed. Missing wiki access does not block advice or source work. A requested wiki write may need a destination clarification; report it as pending rather than creating a sidecar.

## Look up guidance

Consult [the plugin map](plugin-map.md) when specialist guidance would help. Cite useful guidance without requiring an architecture entry, evidence note or backlog item merely to answer a question.

## Orient or refresh

Summarize the goal, current work, relevant records and uncertainty. An optional [state page](templates/state-page.md) can map the project's wiki records. Maintain it when useful within the task; do not invent approvals or impose a new phase.

See [adoption](adoption.md) for existing projects and [decision routing](decision-routing.md) for role suggestions. Neither requires a fixed preamble.
