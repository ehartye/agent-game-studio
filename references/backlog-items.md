# Maintaining backlog items

Keep Studio-maintained backlog and roadmap state in the project's wiki, with a single canonical record per item. Use the project's established wiki formats and statuses. The [template](templates/backlog-item.md) is optional, not a mandate to replace older items.

A useful item states outcome, scope, dependencies and how success can be checked. Include design, art, writing, quality and technical implications only when relevant. An absent fit verdict or design page does not block authorized implementation.

Keep status accurate and record real blockers. Dropping a prerequisite does not itself satisfy a technical dependency. Maintain relevant items when the task calls for it; do not create an item for every consultation.

Existing project-owned trackers are not automatically Studio state. Link them where useful rather than creating competing progress records. Any requested transition to wiki maintenance should preserve history and establish one canonical home, not silently relocate owner content. Use the existing roadmap generator if the wiki roadmap is generated.
