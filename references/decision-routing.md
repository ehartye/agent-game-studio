# Choosing a role

Roles offer useful perspectives and document stewardship, not exclusive editing or decision rights. Choose one or several when helpful; a single agent may apply multiple perspectives.

| Question | Useful role | Advice and wiki records |
|---|---|---|
| Where are we and what records exist? | studio-start | Optional orientation and artifact map |
| What player experience matters? | game-master | Vision, pillars, tradeoffs and brief |
| Which technical option fits? | game-architect | Architecture and technical decisions |
| What next; what depends on it? | game-pm | Priorities, dependencies, backlog, roadmap and status |
| Does it work; how can we know? | game-quality | Test strategy, risks, evidence and defects |
| What should the game say? | game-writer | Narrative, glossary, text and localization backlog |
| What should it look and sound like? | game-artist | Art/audio direction, inventory, provenance and asset backlog |
| How should a system play? | game-designer | Mechanics, balance, specs and experiments |

The user and project retain authority, including delegated decisions. There is no required routing line or output record. For requests outside these examples, use judgment and continue.

Specialist craft help is in [the plugin map](plugin-map.md). Maintained Studio records belong only in the project's wiki.
