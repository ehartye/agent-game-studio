# Optional tooling review

Use this when asked for help with confusing or redundant tooling. It is not required at startup, adoption or a milestone.

Inspect relevant project instructions, skills, integrations, automation and configuration using the host's discovery mechanisms. [Host notes](hosts/README.md) may help. Stay within scope and never copy secret values into notes.

For material findings, explain evidence of use, a useful change, risk and reversibility. Missing usage logs do not prove something is unused. Do not turn advice into enforced checks automatically.

A review can be an answer in chat. If a durable record helps, use [the template](templates/tooling-audit.md) in the project's wiki. Apply changes when authorized, including explicit delegation, under normal project and host rules. Studio adds no approval gate or file-edit restrictions.
